# 今天你想离职了吗？· 工作日记（前端 MVP）

一份安静、克制的职场记录工具：选一个心情，或者随手写一句，把工作里发生的事慢慢记下来；需要的时候再整理成事件、补充材料，并生成一份结构化报告。

> 这是一个**本地前端演示版本**。所有 AI 能力、文件提取与报告判断均为**模拟实现**，不接入真实大模型，不接入云存储、支付或律师服务，也不提供法律结论。

## 启动方式

```bash
npm install
npm run dev        # 本地开发，默认 http://127.0.0.1:5173
npm run build      # 类型检查 + 生产构建
npm run preview    # 预览构建产物（http://127.0.0.1:4173）
npm test           # 单元规则测试（Vitest）
npm run test:e2e   # 浏览器流程测试（需要先 npm run build，并安装 chromium）
npm run format     # Prettier 格式化
```

技术栈：React 19 + TypeScript + Vite + Tailwind CSS v4 + React Router + Zustand。图标与插画全部是**原创手绘 SVG**（`src/components/doodles.tsx`），不再使用任何现成的线性图标集，也不使用第三方品牌素材。

## 信息架构

三个一级导航：**今天 / 回顾 / 我的**。原首页、每日记录、每日结果和 AI 助手全部合并进「今天」，没有独立的 AI 助手板块，也不再有提交后强制跳转的结果页。

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/onboarding` | 首次引导 | 4 步，但只有「当前工作状态」必填，其余每一步都可以跳过 |
| `/today` | 今天（今天） | 日期 + 心情 + 工作记录与 AI 对话 + 今日整理 + 今日留痕建议 + 今日摘要 |
| `/today/:date` | 今天（指定日期） | 从回顾的日历进入历史某一天，恢复当天状态、对话与整理结果 |
| `/review` | 回顾 | 默认只展示日历、近期记录和已确认的重要事件 |
| `/review?tab=events` | 事件列表 | 次级入口：筛选、搜索、新建事件 |
| `/review?tab=materials` | 材料库 | 次级入口：筛选、搜索、上传 |
| `/review?tab=pending` | 待补充材料 | 次级入口：未处理的留痕建议 |

| `/report` | 报告 | 范围选择、预览、打印 / 另存为 PDF、下载 Markdown |
| `/profile` | 我的 | 档案编辑、基础材料、隐私说明、通知偏好、演示设置、数据管理 |

## 今天：普通日子的最短路径

**打开 → 选一个心情 → 保存 → 完成。** 不需要聊天，不需要确认事件，也不需要上传材料。

「今天」页面从上到下包含：

1. **顶部插画**：原创陪伴角色「小本」（身体就是一本日记）坐在书桌前写日记，旁边是窗户、热饮和摊开的日记本。移动端约占首屏 20%（170px），不占满首屏，也不挡下面的主要操作；视口高 ≤480px 的矮屏（横屏手机、矮窗口）自动压到 110px。
2. **一句短问候**：按当前时间给一句（早上好 / 下午好 / 晚上好…）；打开历史日期时改为「回到 X月X日 周X」。
3. **日期**：星期与前后一天切换、跳到指定日期、保存状态（未保存 / 保存中 / 已保存 / 保存失败）、已确认事件入口。
4. **心情**：7 个手绘表情，每个配一个短标签，是当天**唯一**的状态入口（没有压力刻度、没有工作时长）。选中态用该情绪自己的淡色底 + 深墨描边。
5. **工作记录与 AI 对话**：记录区像一页干净的日记纸（很淡的方格纸底纹），提示语「今天工作怎么样？随便记一句。」；提供 5 个快捷话题；助手消息带一个小小的陪伴角色头像，气泡用淡色底 + 细描边；多行输入、明确的发送按钮、中文输入法组合期间不会误发送、发送中防重复提交、失败保留输入并支持重试。保存成功时角色会轻轻动一下（一次性动画）。
6. **今日整理（可折叠）**：AI 整理出来的一般候选安静地待在这里，不弹表单、不打断记录。
7. **今日留痕建议**：只列出确实缺失的材料，用便利贴样式（淡黄底 + 深墨描边 + 一小段纸胶带）；没有需要补充的显示「今天暂无特别需要补充的材料。」
8. **今日摘要**：移动端为折叠面板，桌面端为右侧可折叠摘要栏，包含今天的状态、AI 今日总结、待确认的整理结果、已记入回顾、待补充材料。

已发送的内容立即保存；**输入框里还没发送的文字也会作为草稿保留**，刷新后可以接着写。每个日期维护独立记录与对话，重新打开会恢复内容。

## AI 的行为边界

AI 是**记录过程中的整理助手**，不是聊天机器人。核心原则是**减少打扰**：

| 用户说什么 | AI 怎么做 |
| --- | --- |
| 只说累 / 情绪表达 | 回应情绪，**不创建事件** |
| 描述具体变化 | **默认用已有信息直接整理**（日期就用这一天，人物从原话里抽），不要求填完整表单 |
| 时间说不清（「前几天」） | 只补问一句「大概哪一天」，其余不追问 |
| 值得及时关注的变化 | 在对话里给一张轻量卡片：**记下来 / 先放着 / 不记录**，默认用已有信息，可展开编辑 |
| 一般进展（如被表扬） | 只进「今日整理」，不在对话里打扰 |
| 问「该保存什么」 | **先查材料库存**，只列出确实缺失的部分 |
| 当天签文件等时间敏感事项 | 展示「整理当前情况」卡片，由用户主动进入，不自动跳转 |
| 补充已确认事件的新情况 | 建议「追加进展」，不新建重复事件、不自动改写已确认内容 |

「先放着」保留草稿，不会反复弹出。确认后只显示「已记入回顾」，不强制进入事件详情，也不要求上传材料。所有 AI 输出都带「模拟 AI」标识，规则模板不会被包装成真实模型分析。

## 留痕建议与材料收集

这是核心功能，既不在「回顾」里被埋没，也不以确认事件为前提。

| 场景 | 表现 |
| --- | --- |
| 普通工作日 | 不生成收集任务，轻量显示「今天暂无特别需要补充的材料。」 |
| 有具体职场变化 | 当天记录中直接出现简短的「今日留痕建议」卡片 |
| 时间敏感事项 | 建议标记「建议优先保存」，排在待处理列表最前 |

卡片操作：**上传 / 我已自行保存 / 稍后 / 不需要**。

规则：

- 材料收集**不以确认事件为前提**：建议先挂在当天的每日记录上，事件确认后再建立事件关联。
- 保存材料**不会自动确认事件**。
- 已有且有效的材料不重复要求收集（`matchingMaterials` 按类型 + 事件 + 是否当前有效判断）。
- 工资、考勤等持续材料只建议补充缺失时间段（`missingRanges` 求未覆盖区间）。
- 同一天继续聊天时更新已有建议，不重复创建卡片（按类型 + 归属 + 区间 + 标题去重）。
- 用户可以不处理建议，直接结束记录；未处理建议保留在当天记录与回顾的「待补充材料」中。
- 上传或标记自行保存后，今天、回顾与材料库存同步更新。

## 回顾：默认保持安静

默认只展示三块：**情绪日历**、**近期记录**、**已确认的重要事件**（优先处理 > 值得关注 > 普通）。

事件列表、材料库、待补充材料、报告都是次级入口，默认不堆满统计卡片、风险提示和待办。**未确认的草稿不会进入回顾。**

### 情绪日历

- 白底 + 很淡的方格纸纹理（`rgba(41,40,36,0.055)` 的细线），七列布局，格子之间**没有明显边框**，靠留白分隔，读起来像一页心情日记。
- 月份是主标题（手写体），年份是次要文字；上一月 / 下一月按钮与「回到今天」在同一行；左侧一个小型陪伴角色，装饰不挤占标题与操作区。
- 星期行固定为 `一 二 三 四 五 六 日`，从真实年月计算，正确处理每月开头的空位与当月天数。
- 每天只有一个主心情角色，不做双行表情，也**不要求一天填两次心情**。
- 情绪映射（形状与表情共同区分，不只靠颜色）：开心→淡黄笑眼、还行→淡橙放松、一般→淡绿平静、疲惫→灰蓝垂眼（带一个 z）、生气→珊瑚红方脸竖眉、焦虑→淡紫睁大眼加汗滴、委屈→淡粉垂眉加眼泪。
- 日期状态：

| 状态 | 表现 |
| --- | --- |
| 记了心情 | 日期 + 对应的手绘心情角色 |
| 记了内容但没选心情 | 日期 + 一个中性的手绘日记本图标，**不猜情绪** |
| 今天未记录 | 日期位置显示「今天」，下面一个淡色手绘「＋」轮廓；点进去就是今天的记录页 |
| 过去未记录 | 浅灰日期 + 一个空心小点，不呈现成失败任务 |
| 未来日期 | 只显示弱化的日期，不可点，也不会创建未来的日记 |
| 今天已记录 | 保留心情角色，并用一道浅描边标记今天 |
| 有已确认事件或待补充材料 | 在角色下方加一个小圆点；具体内容进入当天记录后查看，不把事件标题和材料数量堆进格子里 |

- 日历下方是手绘铅笔记录入口：淡黄底 + 深墨描边，未记录时显示「今天还没写日记」并写「记录今天」，已记录后改成「继续记录今天」；移动端不会与底部导航重叠。
- 「今天」页没有单独的本周日历，因此不存在两套视觉素材的问题；如果以后加周历，直接复用同一套 `MoodFace` 与日期状态规则。

## 数据存储

| 内容 | 位置 |
| --- | --- |
| 工作档案、每日记录、事件、材料元数据、留痕建议、对话、设置 | `localStorage`（键名 `workday-companion-v1`） |
| 上传的原始文件（PDF / PNG / JPG / TXT） | `IndexedDB`（库名 `workday-companion-files`） |

- 文件本体不放进 `localStorage`，只保存 `fileId` 等元数据。
- 每日记录（`DailyEntry`）通过 `conversationId` / `eventIds` / `suggestionIds` 关联当天的对话、事件与建议，并用 `draftText` 保存未发送的文字。
- 消息（`ChatMessage`）带 `dailyEntryId` / `conversationId` / `status`，因此**每日记录是对话的来源**；事件与材料仍是独立对象，方便时间线与报告引用。
- 留痕建议（`MaterialSuggestion`）带 `entryId`，`eventId` 可以为空——这正是「材料可以先于事件存在」的数据基础。
- 旧版本数据在启动时由 `src/services/migrate.ts` 自动补齐新字段（v1→v2→v3），不需要手动清理。
- 刷新页面后数据与文件仍可访问；清空浏览器数据或使用无痕窗口会导致数据不可访问。
- 「我的 → 数据管理」可导出演示数据 JSON、重置演示故事、清空本地数据（同时清理 IndexedDB）。

## 设计风格：手绘日记本

取消此前的「蓝白灰办公软件」风格，改成手绘日记本的感觉。令牌集中在 `src/index.css` 的 `@theme`：

| 用途 | 值 |
| --- | --- |
| 页面背景 | `#FFFEFB` |
| 卡片 / 内容底色 | `#FFFFFF` |
| 描边与标题 | `#292824` |
| 正文 | `#484640` |
| 次要文字 / 弱文字 | `#6F6A62` / `#857F77` |
| 线条（次级区块） | `#E2DDD1` |
| 淡蓝 / 淡绿 / 淡黄 / 淡粉 | `#DDEEFF` / `#E7F0CE` / `#FFF0D0` / `#F9DED5` |
| 淡橙 / 淡紫 / 灰蓝 | `#FFE7CE` / `#E7DDF4` / `#DCE3EA` |
| 成功 / 提醒 / 紧急 | `#4C7A34` / `#9C6A1F` / `#B8533D` |

- **描边与卡片**：白底 + 1.3–1.6px 深墨描边 + 略不规则的圆角（如 `15px 13px 16px 12px / 13px 16px 12px 15px`），不投影、不渐变、不用玻璃拟态。手绘感来自描边与圆角变化，**卡片本身不倾斜，文字保持对齐**。
- **轻重层次**：主区块 `.panel` 用深墨描边；次级区块 `.card` / `.panel-flat` / `.list-row` 用暖灰细线。整页不会到处是黑框。
- **颜色只用在小地方**：插画底色、选中态、便利贴、小标记。文字始终用深墨或正文色，保持清晰对比。
- **手写体只用于短标题与装饰文字**（`h1` / `h2` / `.hand`），正文、表单、报告一律用清晰系统字体。
- **图标与插画**：27 个图标 + 7 个心情角色 + 陪伴角色 + 顶部插画全部是原创 SVG（`src/components/doodles.tsx`），统一深色描边与同一线宽（靠 `vector-effect: non-scaling-stroke` 保证任何尺寸下线宽一致），不混用标准线性图标集与卡通图标集。**心情选择与日历里不再出现系统 emoji。**
- **动效**：只有一次性轻微动作（保存成功时角色 `animate-pop`），没有持续抖动或弹跳；并且支持系统的 `prefers-reduced-motion`。
- **桌面端**：左侧三项导航 + 中间记录区 + 右侧可折叠摘要栏（今日摘要 / 今日整理）。
- **移动端**：三项底部导航，选中项用淡蓝色块 + 细描边；输入框吸附在导航之上，键盘弹出时优先保证输入区可见。
- **触屏可点区域**：偏小的图标按钮（前一天 / 后一天、上个月 / 下个月、留痕建议的「处理 / 稍后 / 不需要」）在移动端撑到 44×44（`.tap` / `.tap-square`，见 `index.css`），满足 iOS HIG 的最小可点尺寸；桌面端用鼠标，保持原来的紧凑版式。
- **紧急提示保持醒目**：时间敏感事项用淡粉底 + 更粗的深墨描边 + 盾牌图标，不用可爱插画削弱。
- **关注程度同时用文字表达**（普通 / 值得关注 / 优先处理），不只靠颜色。
- 产品使用自己的名称、角色与图标，未使用任何第三方品牌素材。

视觉走查截图放在 `outputs/shots/`，可用 `node scripts/shot.mjs` 重新生成（需要先 `npm run build` 并启动 `npm run preview`）。

响应式走查用 `node scripts/responsive.mjs`：会跑 8 个宽度（320 / 360 / 390 / 414 / 768 / 1024 / 1280 / 1440）× 13 个页面，检查横向溢出、导航模式切换，并打印溢出元素明细。

## 已实现的产品规则

1. 只选心情就能完成当天记录；状态只有心情一项，没有压力刻度与工作时长输入。
2. 未发送的文字作为草稿保留，刷新后可以接着写。
3. AI 默认用已有信息整理，只有时间说不清时才补问一句，不要求填完整事件表单。
4. 一般事件候选放进可折叠的「今日整理」；只有值得及时关注的变化才在对话里给轻量卡片。
5. 确认后显示「已记入回顾」，不强制跳转事件详情或上传材料；「先放着」保留草稿且不反复弹出。
6. **未确认事件不进入回顾时间线与报告**；同一草稿重复确认不会生成重复事件（按来源 + 标题去重）。
7. 材料收集不以确认事件为前提，建议先挂在当天记录上；保存材料不会自动确认事件。
8. 生成建议前先查材料库存；已有且有效的材料不重复要求收集；工资 / 考勤只建议补充缺失时间段。
9. 材料建议的处理入口（对话卡片、今天、回顾、事件详情）共用同一处逻辑（`components/suggestion-actions.tsx`）。
10. 继续聊天可以更新 AI 总结，但**不会自动改写已确认事件**；补充内容只作为「追加进展」由用户确认。
11. 情绪与日常状态分享不会写入合同、工资、HR 沟通、事件、材料或报告。
12. 报告只包含已确认事件；未确认摘要只标注「摘要待确认」，不进入事实；日期范围筛选真实生效。
13. 不使用「公司违法」「一定能赢」「你必须辞职」等表述；关注程度使用普通 / 值得关注 / 优先处理。

### 重点验收对照（产品流程）

| 验收点 | 覆盖方式 |
| --- | --- |
| 1. 普通日子只选心情或写一句就能完成记录 | `保存今天` 只需心情；`flow.spec.ts` 两条用例分别覆盖「只选心情」与「写一句」 |
| 2. AI 对话直接在每日记录中继续 | 对话内嵌在 `/today`，多轮追加不跳页 |
| 3. 不强制跳转结果页、确认事件或上传材料 | 确认后仅显示「已记入回顾」；`flow.spec.ts` 断言 URL 仍在 `/today` |
| 4. 有需要时当天直接出现留痕建议 | `/today` 的「今日留痕建议」区块；`day-suggestions` 测试标识 |
| 5. 用户未确认事件也能保存相关材料 | 建议带 `entryId` 且 `eventId` 为空；`flow.spec.ts` 在草稿未确认时处理材料 |
| 6. 已有材料不重复提醒 | `matchingMaterials` + `createSuggestions` 去重；`materials.test.ts` 覆盖 |
| 7. 未确认事实不进入正式时间线和报告 | 回顾与报告只取 `confirmed`；`ux.spec.ts` 与 `materials.test.ts` 断言 |
| 8. 刷新后记录、对话、材料和处理状态仍然保留 | `flow.spec.ts` 刷新后断言消息、整理结果与材料处理状态 |

### 重点验收对照（手绘视觉）
